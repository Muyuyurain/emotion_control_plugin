## 简介

本插件让聊天机器人具备"当前情绪状态"：模型在回复首行自行报告情绪变化，插件将该行剥离并记账，下一轮再以"词语"形式注入回上下文。

整条链路不额外调用模型，也不向模型暴露数值读数。

```
模型输出                          用户看到                     插件记账
┌──────────────────────────┐    ┌──────────────────────┐   temper / mood / emotion
│ @E v=+0.02 a=+0.15 d=+0.05│ → │ 先看 error log，502  │ → 三层状态 + 按用户 trust
│ 先看 error log，502 …     │    │ 基本都是上游没起来。 │
└──────────────────────────┘    └──────────────────────┘
```

即时通讯网关以整条消息投递，被剥离的首行用户不可见，因此该协议在此类平台上是可行的。代价是模型必须**愿意**输出这一行，配置方法见「启用模型自报」。

## 兼容性

- 运行于支持插件钩子（`pre_llm_call`、`transform_llm_output`、`post_tool_call`、`on_session_end`）的宿主 Agent 框架。
- 数据目录遵循宿主框架的插件存储约定；无法解析时回退到 `<HERMES_HOME>/plugin-data/emotion_control/`。
- 目前截至插件上传前，作者本人使用的Agent框架为Hermes Agent v0.22.0+38.g1f6c02c.dirty (2026.9.24)，其他版本可能存在钩子行为差异，请自行验证。

## 安装

将本仓库内容放入宿主框架的用户插件目录（例如 `$HERMES_HOME/plugins/emotion_control/`），随后启用：

```bash
hermes plugins list                 # 确认插件已被发现
hermes plugins enable emotion_control    # 加入启用列表
```

插件注册的钩子在网关进程重载后生效。

数据默认落在 `<HERMES_HOME>/plugin-data/emotion_control/emotion.db`（WAL 模式）。调试时可用环境变量覆盖路径：`EMOTION_CONTROL_DB=/tmp/x.db`。

## 与同类插件不可同时启用

若同时启用另一套情绪状态插件，会产生如下问题：

- 提示词中出现两套互相矛盾的"当前状态"读数，模型行为不可预测；
- 两套状态各自演化，排查时无法对齐；
- 每轮产生额外的 SQLite 读写。

请仅保留其中一个。

## 启用模型自报

插件**仅在模型确实输出 `@E` 行时**才记账。需在人格或系统提示中加入如下协议说明：

```text
【情绪自报协议】
每次回复的第一行，用下面这一行报告你这轮的情绪变化（范围 -1.0 ~ +1.0，可正可负）：
@E v=<效价> a=<唤醒> d=<把握>
v 越正越愉快，a 越高越兴奋/急，d 越高越有把握。
没有明显变化就写 @E v=0 a=0 d=0（插件会把全 0 当作"未报到"，不会清零）。
这一行会被插件剥离，用户不可见；正文从第二行开始。
```

缺少该说明时插件不会报错，但情绪层将长期停留在 `temper` 基线。

## 情绪模型

```
temper   常驻底座，不随对话变化        v=+0.05  a=+0.15  d=0.00
mood     = temper + Σ(事件 × e^(-Δt/2h))
emotion  = mood + 本轮尚未结转的 impulse   （impulse 的快速时间常数 20min）
```

单次自报仅进入 `impulse`，下一轮开始时整体结转进 `mood` 账本。同一笔事件在任一时刻只存在于其中一个容器中，因此不会出现重复放大。

各轴边界不对称，且单笔限幅：

| 轴     | 下限  | 上限  | 单笔上限 |
| ------ | ----- | ----- | -------- |
| v 效价 | -0.55 | +0.85 | 0.10     |
| a 唤醒 | 0.00  | 1.00  | 0.10     |
| d 把握 | -0.60 | +0.60 | 0.08     |

负向边界收得更紧：若采用对称的 ±1.0，仅一小时内 30 笔 -0.08 即可使 v 长期固定在 -1.000，难以恢复。

账本定期剪枝：权重低于 0.01（约 9 小时）的事件会被删除，硬上限 2000 条。

## 注入内容

```
[此刻] 心情 略沉｜唤醒 中｜把握 偏低
[关系] 信任 初步｜熟悉 0.2
[边界] 情绪只改语气与详略，不改事实判断、安全边界与确认习惯。
[边界] 可以话少、可以直接、可以说不看好；不可冷淡、说教、阴阳怪气；该给的命令与风险提示一条不少。
```

**故意不提供数值**：模型看到 `-0.12` 之类的读数会将其当作目标值，下一轮报 `+0.02`、读数仍为 `-0.12` 时继续报 `+0.02`，形成闭环。使用词语描述则不存在可对齐的目标值。

两条 `[边界]` 永不裁剪：预算不足时优先丢弃可选行，其次丢弃关系行。宁可减少一句情绪描述，也不能让模型在情绪低落时省略命令或风险提示。

## 命令行

```bash
hermes emotion show                 # 三轴当前值、temper、trust、事件数
hermes emotion show --user demo:12345 # 附加该用户的 trust / familiarity
hermes emotion tail -n 20           # 最近自报审计：原始首行与解析结论
hermes emotion explain              # 按贡献绝对值排序，显示影响 mood 的事件
hermes emotion set v 0.12           # 手动设置 temper（v/a/d 之一），越界会被压到边界
```

`tail` 可区分四种非正常情况：`未写标签`、`标签格式错误（无数字）`、`标签全 0（未报到）`、`仅标签无正文（替换为占位符）`。

## 降级行为

全部 fail-open：

| 情况                                              | 行为                                                       |
| ------------------------------------------------- | ---------------------------------------------------------- |
| 数据库无法打开或写入失败                          | 记录 warning，回复照常投递（不记账）                       |
| 首行为 `@E` 但数字无法解析                      | **仍然剥离该行**，仅不记账                           |
| 剥离后正文为空                                    | 替换为 `……` 占位符，既不投递空消息，也不使 `@E` 泄漏 |
| 首行不是 `@E`、但正文中某一整行只有标签和 token   | 剥掉那一行并照常记账，其余正文原样投递                     |
| 模型未输出标签                                    | 原样透传                                                   |
| 子 agent（`parent_session_id` 非空）            | 不注入、不记账                                             |
| 同一 `(session_id, turn_id)` 在 300s 内重复投递 | 仅记录一次                                                 |
| 数据库不可用但存在 `@E` 行                      | **仍然剥离**（剥离先于落库）                         |

## 配置

配置键位于插件设置中，均为可选项：

```yaml
plugins:
  entries:
    emotion_control:
      settings:
        enabled: true
        injection_budget: 400      # 注入文本字符预算
        tau_event: 7200            # 账本时间常数（秒）
        tau_impulse: 1200          # 快分量时间常数（秒）
        max_events: 2000           # 账本硬上限
        dedupe_ttl_seconds: 300    # 幂等窗口
        trust_base: 0.35           # 新用户 trust 基线
        trust_step: 0.02           # 单轮 trust 最大步长
        familiarity_step: 0.01     # 每轮 familiarity 增量
        halve_min_gap: 10800       # 衰减最小间隔（秒），默认 3 小时
        skip_on_risk: true         # 高风险任务跳过本轮注入
```

## 离线回放

不依赖宿主框架、不调用模型，使用假时钟与临时数据库：

```bash
python demo.py
```

该脚本调用与线上相同的函数（`hooks.begin_turn` / `hooks.apply_output`），并验证：

1. 每轮"注入值 → 自报 Δ → 结算值"的结算差与自报 Δ 相等；
2. 中途关闭并重建 Store 后，读数与账本保持连续；
3. 连续 10 轮 `@E v=-0.10` 后停在 -0.550 下限。

## 实现注意

- 宿主框架的 `on_session_end` 钩子实际在**每轮结束**时触发，而非会话结束。因此衰减必须走带时间闸门的 `halve_if_due()`，否则每轮都会折半。
- 闸门的"读取 → 判断 → 折半 → 写回"必须在同一写锁与事务内完成，避免并发收尾导致重复折半。

## 已知限制

- 自报通道依赖模型配合。模型可能遗漏标签、写错标签或只写标签不写正文；三者均有兜底，但"遗漏标签"的那一轮无法补记。
- 幂等键优先使用 `(session_id, turn_id)`；仅在无法取得 `turn_id` 时退化为全文哈希。
- `agent_state` 为全局单份，即一个进程对应一个人格。暂不支持多租户场景。

## 高风险任务守门

情绪层的 `[边界]` 属于提示词级约束，依赖模型自觉。涉及删除数据、修改防火墙、提权等操作时，额外的情绪提示只会增加风险。因此策略为：**本轮涉及危险操作时，情绪层不注入**。

命中规则分为两类：

- 危险命令：`rm -rf`、磁盘格式化命令、`dd if=`、`DROP TABLE`、`TRUNCATE`、`DELETE FROM`、`chmod 777`、`chown -R /`、`shutdown/reboot`、`iptables -F`、`firewall-cmd --panic`、`systemctl stop/disable`、`passwd root`、`authorized_keys`、`git push -f`、`docker rm/prune` 等；
- 危险意图：删库、删表、清空数据、格式化、关闭防火墙、开放端口、提权、免密登录、跳过备份等。

规则刻意宽松：误判的代价仅是"本轮没有情绪提示"，漏判的代价则可能是模型在修改防火墙时仍带情绪描述。命中任意一条即跳过注入，但账本结转照常进行。

```yaml
skip_on_risk: false      # 需要关闭时
```
